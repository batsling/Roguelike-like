# Roguelike Radio

The player's own music, unlocked by playing the real games, played into OBS (or
out of the game window). This is the design and the reasoning; the code is
`scripts/autoload/Radio.gd`, `scripts/ui/RadioScreen.gd` and the `radio` card in
`obs/`.

## 1. What the owner asked for

- Songs unlocked by **"do X goals on this game"** and **"beat this game X
  times"**.
- The music is **music the owner already owns**. It is never committed.
- Songs are authored in **the spreadsheet**: name, artist, album, year, game,
  album image and tags, plus the unlock rule.
- **Nothing is unlocked by hand.** A song unlocks the moment its count is met,
  and that includes counts the save already holds.
- It plays **into OBS**, with a setting to play it **from the game window** when
  OBS isn't running.
- **Skip, back, pause and volume** are available from anywhere.
- It plays **the whole time the game is open** (menus and runs), **shuffled**,
  with **tags as stations**.
- A new unlock gets a **toast** in the game and on the overlay, and **plays
  next**.

## 2. The `radio` sheet

`tools/Roguelikes.xlsx` → `radio`, generated by `tools/generate_song_tres.py`
into `data/songs/*.tres` (`SongData`). Edit the sheet and regenerate, as for all
content. The sheet was created by `tools/_radio_sheet_setup.py` with one example
row (No Escape, Hades); delete it freely.

| Column | Meaning |
|---|---|
| `Name` | the song's title |
| `Artist` | who made it |
| `Album` | optional |
| `Year` | optional |
| `Game` | the game it belongs to **and unlocks on**: its name as the `games` sheet spells it, or its id. Must be in the catalog |
| `Unlock` | `goals` or `wins`. **Blank keeps the song locked.** That is the owner's rule: a row still being authored should not start playing on stream |
| `Count` | how many it takes (1 or more when `Unlock` is set) |
| `File` | the exact file name in the music folder: `.mp3`, `.ogg` or `.wav` |
| `Image` | album art base name under `images2.0/radio/` (blank = the game's cover) |
| `Tags` | comma-separated, lower-cased; every tag is a station |

The generator **rewrites** `data/songs/`: a row deleted from the sheet takes its
`.tres` with it. It refuses an unknown game, an unknown `Unlock` word, an
`Unlock` with no `Count`, an audio extension it can't play, and two rows that
come out as the same id (`<name> <artist>`, slugified).

## 3. Unlocking

| Rule | Counts | Source |
|---|---|---|
| `goals` | every goal-enemy beaten **at that game**, re-clears included | `GameStats.goals_count(game)` (sum of `enemy_log[game][*].beaten`) |
| `wins` | every time **that game** was reported beaten | `GameStats.beaten_count(game)` |

The owner chose **enemy goals only** for `goals`. Level-ups and status goals
don't count.

Both counts already existed for every game, so **the radio stores no progress
of its own**. A song is unlocked exactly when `have >= need`. The only thing it
remembers (per profile, `radio.json` in the profile folder) is which unlocks it
has already **announced**, so each one gets its toast and jumps the queue
exactly once.

- **Re-checked on every `GameStats.changed`**, which a report always emits.
- **At boot and on a profile switch, unlocks are taken quietly.** A first launch
  on an old save could otherwise owe dozens of toasts.
- **An unlocked song whose file isn't in the folder** is listed as "file not
  found" and skipped. A typo in `File` then shows up as a typo, not as a song
  that silently doesn't exist.

## 4. Playing it: the game keeps the clock

The music can come out of two speakers: `radio.html` in OBS, or the game window
(an `AudioStreamPlayer` on the `Radio` node). **The OBS page can't talk back.**
There is no server; the game only writes a file the page reads
(`ObsCompanion`). So the page can't say "this song ended", and the radio keeps
time itself:

- **At the start of each track** the stream is loaded and its length read
  (`get_length()`). This is also why only mp3/ogg/wav are supported: those are
  the formats Godot can load at runtime and measure.
- **The position** is `offset + (now - since)` while playing, and `offset` while
  paused.
- **When the position passes the length**, the radio moves on.
- **The page is told** the track, `offset`, `since` (unix seconds), whether it is
  playing, and a `seq` number that moves on every start, restart, pause and
  resume. It seeks when `seq` changes, and otherwise only corrects drift of more
  than 2 s.
- **A refreshed OBS source** picks the song up where it is.

Nothing in the payload moves between changes, so `ObsCompanion`'s dedupe still
treats an unchanged radio as unchanged. The page works out the running position
from `since` on its own.

**One speaker at a time, chosen by a setting.** The page can't tell the game
it's open, so "play in the game when OBS isn't running" can't be detected. The
other speaker stays silent so nothing ever plays twice. For the same reason
**only `radio.html` plays**: every view is the same page, and a scene with the
checklist, the map and the timer in it would otherwise play the music three
times over, out of step.

**The track is staged beside the page** (`user://obs/radio/`, only the current
one kept), for the reason the covers are: nothing the page loads may point
outside its folder, or OBS's browser source refuses it (README, "The stream
overlay").

## 5. The queue

- **Shuffle** (the default) deals every playable song on the station once
  before any repeats. The song just played never opens the next pass.
- **In order** walks the catalog in id order.
- **A new unlock** is pushed onto the front of the queue.
- **Back** restarts the song if it is more than 3 s in; otherwise it goes to
  the previous song (a history of 50).
- **A station** (a tag) filters the playable list. "All songs" is no filter.
- **A file that won't decode** is skipped, and remembered for that pick so a
  folder of broken files ends in silence rather than a loop.

## 6. Where the controls are

`RadioScreen`, opened from **📻 on the run's header bar** (beside Map and Menu,
on the layer no modal covers) and from **Radio in the main menu's top-right
corner**. It has:

- what's playing and how far in;
- Back / Pause / Skip and a volume slider;
- shuffle, the station, and where it plays from;
- the music folder, with Open folder and Rescan (for files added while the game
  is running);
- every song on the sheet: unlocked first, then the nearest to unlocking, each
  with its rule and progress ("Do 5 goals in Balatro (3 / 5)") and a ▶ to play
  it now.

The speakers, volume, shuffle, station and pause live in `user://radio.cfg`.
They belong to the PC, like the window mode does, not to a profile.

## 7. Setting it up (for the streamer)

1. Put the music in the folder the Radio screen shows (`Open folder`).
2. Add a row per song to the `radio` sheet, with `File` matching the file name,
   and regenerate.
3. In OBS, add a Browser Source with "Local file" ticked, pointed at
   `radio.html` in the overlay folder, sized about 352 × 100.
4. In OBS's Advanced Audio Properties, set that source's Audio Monitoring to
   **Monitor and Output** to hear it yourself. Untick it on the VOD track if the
   music shouldn't be in the recording.
